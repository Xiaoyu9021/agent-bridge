# 开发计划与交付标准

目标：将真实的 Windows Android 开发 → Mac iOS 开发交接场景做成可公开审阅的 GitHub 项目。当前唯一实现范围是 V0.1。

## 产品入口调整：以 skill 为主要交付

用户明确的第一目标是 SpaceWatch 开发中 Mac 执行包/报告 → Windows 总指挥的直接交接，替代手机中转。交付从桌面程序改为 `skills/agent-bridge`：用户在 Codex 对话中操作，后台工具收发，Agent 收取后直接读取报告。已有桌面代码保留为原型，网络/存储核心复用。

| 当前阶段 | 状态 |
|---|---|
| S1 自包含 skill、自动环境、后台收件、Agent 命令 | 已实现，Windows 独立运行环境验证通过，无 Qt |
| S2 三附件发送、收取、实际阅读后确认、重试与重启 | Windows 两后台进程、独立 CLI 与系统凭据库实测通过 |
| S3 Mac skill 安装与真实 LAN 基本双向交付 | 已完成，双方各 3 个合成附件，报告阅读与已读回执闭环 |
| S4 真实 SpaceWatch 工作交付试运行 | 2026-11-03 用户确认通过；未将真实工程/报告纳入公开证据 |
| S5 GitHub 仓库、线上 CI 和首次发布 | 独立公开仓库已创建，准备推送并取得线上结果 |

当前不接入自动 Agent 执行、聊天窗口接管、MCP、额度检测或 Git 接力。先完成用户指定文件和报告在两个 Codex 之间的交接。下表 M1–M5 是此前桌面原型的历史里程碑。

## 技术取舍

- 单代码库 Python + PySide6；业务核心脱离 UI。FastAPI + httpx，3–5 秒轮询。
- Host 为中心存储，离线目标上线后拉取；Client SQLite 缓存供断网查看。
- SQLite 事务和 UUID 幂等键；先创建草稿和附件清单，文件校验齐全后显式发布。
- 附件在 UUID 路径落盘；按块处理，失败清理临时文件，重试从头开始。
- Host 本地控制面负责配对授权，远端 API 不提供管理员操作。
- 默认回环监听；LAN/Tailscale 必须选择具体 IP，拒绝公网和通配监听。
- 不为未来 Agent 适配器创建空壳。数据中保留 schema_version 和 Agent 名称即可。

## 仓库组织

`src/codex_bridge/{models,storage,server,client,services,ui}` 分别负责协议、持久化、服务、客户端、导出与桌面交互。`tests/` 为安全和交接回归；`scripts/` 为构建与联调；`docs/` 为设计、证据和手册。
